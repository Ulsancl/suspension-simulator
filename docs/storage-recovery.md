# 실험 기록 보관과 복구

모델이 바뀌어도 이전 결과를 새 계산으로 바꾸지 않습니다. 이 앱의 현재 모델은 `quarter-car-1.3`이며, 저장 스키마 1의 `quarter-car-1.0`, `1.1`, `1.2` 기록은 설정과 샘플이 유효하면 원래 모델 버전의 읽기 전용 기록으로 엽니다. 기록에 저장된 샘플, 실험 지표, 기존 KPI를 유지합니다. 기존 KPI가 없는 기록은 저장된 샘플에서 통계만 구하며 시뮬레이션을 다시 실행하지 않습니다.

이전 기록은 비교 선택, CSV와 HTML 보고서 내보내기가 가능합니다. 설정 자동 적용, 이름 변경, 동일 ID 덮어쓰기와 개별 삭제는 막습니다. 새 시험은 현재 모델에서 새 ID로 계산합니다. 모델 버전이 다르면 같은 입력 조건이라도 다른 계산 결과가 나올 수 있으므로 기록 카드와 보고서의 모델 버전을 함께 확인하세요.

## 사용 방법

1. 이전 저장이 있으면 실험 보관함의 **이전 저장 원문 보관** 패널을 확인합니다.
2. **원문 내려받기**로 읽기 전용 원본을 별도 파일에 보관합니다. 문자열로 저장된 JSON은 공백과 줄바꿈을 포함해 그대로 내보냅니다. IndexedDB에 객체로 저장된 기존 기록은 그 저장 값을 JSON으로 내보냅니다.
3. **프로젝트 저장**은 현재 설정과 현재 보관함을 저장합니다. 원문 사본과 현재 프로젝트 파일은 서로 다른 목적의 파일입니다.
4. **보관 기록 복구**는 지원하는 원문 사본으로 현재 보관함을 교체합니다. 현재 새 작업을 프로젝트 파일로 먼저 저장한 뒤 실행하세요. 이전 모델 기록은 복구 후에도 읽기 전용입니다.
5. 이전 기록으로 보관함이 가득 찼다면 프로젝트와 원문을 먼저 저장한 뒤 **새 프로젝트**를 시작합니다. 이전 원문 사본은 남아 있으며 복구 패널에서 다시 열 수 있습니다.

현재 앱이 모르는 미래 스키마, 미래 모델과 확인할 수 없는 모델은 손상으로 단정하지 않습니다. 각각 지원하지 않는 형식 또는 모델로 안내하고 원문을 따로 보관합니다. 값이나 JSON 형식이 실제로 잘못된 기록은 손상으로 안내합니다. 지원하지 않거나 손상된 파일은 원문 내려받기만 가능하며 정상 결과인 것처럼 복구하거나 자동 변환하지 않습니다.

## 저장 안전 장치

이전 모델 또는 읽을 수 없는 저장 원문은 기존 저장 위치에 그대로 둡니다. 새 작업은 현재 모델의 별도 저장 영역을 사용합니다. 새 영역에 처음 쓰기 전에 별도 원문 사본과 복구 목록을 저장하고 다시 읽어 내용이 일치하는지 확인합니다. 초기 읽기만으로 원문을 바꾸거나 삭제하지 않습니다.

백업 쓰기, 용량, 백업 내용 확인 또는 복구 목록 확인이 실패하면 기존 원문과 별도 저장 영역을 덮어쓰지 않습니다. 새 계산은 메모리에 남기며 화면에 **메모리 보관 · 프로젝트 파일 저장 권장**을 표시합니다. 이때 앱을 닫기 전에 현재 프로젝트와 필요한 원문을 파일로 저장하세요. 저장 공간을 사용할 수 있게 되면 다음 저장에서 백업을 다시 시도합니다.

현재 모델의 별도 저장 영역 자체를 읽을 수 없거나 복구 목록이 손상된 경우에는 확인되지 않은 영역을 덮어쓰지 않고 새 작업을 메모리에만 보관합니다. 원문과 새 프로젝트를 내려받아 보관하고, 지원하는 정상 프로젝트를 다른 작업 프로필에서 여는 방법으로 복구할 수 있습니다. 원문 패널이 없고 저장 공간 읽기에 실패했다는 안내가 나오면 앱 밖의 저장 데이터에 접근하지 못한 상태이며, 백업되었다고 간주하지 않습니다.

기본 저장소는 IndexedDB입니다. 기본 저장소를 사용할 수 없어 localStorage로 전환하면 그 사실을 알리며 기본 저장소를 수정하지 않습니다. 대체 저장소도 사용할 수 없으면 메모리와 프로젝트 파일을 사용합니다. 브라우저 주소 또는 앱 프로필이 바뀌면 다른 저장소가 열리므로 자동 저장을 장기 보관의 유일한 수단으로 사용하지 마세요.

## 구현과 검증 범위

기존 기본 키 `suspension-lab:experiments:v1`는 이전 버전으로 돌아갔을 때 읽을 수 있도록 유지합니다. 현재 작업 분기는 `:model:quarter-car-1.3:schema:1`, 원문 사본은 `:recovery:...`, 복구 목록은 `:recovery-index:v1`에 보관합니다. 지원되는 현재 기록만 있는 기존 저장의 API와 저장 위치는 유지합니다. 파일 복원은 검사 성공 후에만 현재 보관함을 바꿉니다.

[저장 회귀 검증](../tests/experiments.test.mjs)은 이전 기록 열기, 현재 새 저장, 재시작, 명시적 복구, 새 프로젝트 후 원문 SHA-256 보존을 확인합니다. 미래 스키마·모델, 손상 JSON, 백업 쓰기·재읽기 실패와 저장소 읽기 실패를 별도로 검증합니다. [브라우저 검증](../tests/experiment-migration-browser.test.mjs)은 새 임시 Chromium 컨텍스트의 실제 IndexedDB에서 읽기 전용 화면, CSV, 보고서, 새 시험, 재시작과 복구를 확인합니다. 사용자의 실제 AppData나 설치된 앱 프로필은 검증에서 수정하지 않습니다.
